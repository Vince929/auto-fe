name: memory-extract
description: catpaw-memory 的提取子模块。扫描对话历史，提取有价值的记忆候选项，展示给用户确认后再写入。最多 5 轮，与主 Agent 互斥。
---

## 提取流程

> **定位：** 本模块扫描会话历史，提炼出值得长期保存的信息，**展示候选列表给用户确认，用户批准后才写入**。
>
> **触发时机：** 用户主动说"提取记忆"、"总结一下这次对话"、"帮我记录这次的关键点"等；或会话结束前用户主动发起。

---

### 互斥检查（最优先）

检查本轮主 Agent 是否已写入记忆：

- 检查两层 `MEMORY.md` 的最后修改时间是否在本会话内
- 如果主 Agent 本轮已写入 → **合并到确认列表一起展示**，不单独重复
- 前移读取游标到当前消息位置

---

### Step 1：确认环境

检查以下条件，任一不满足则退出：

- [ ] `~/.catpaw/rules/memory-index.md` 或 `.catpaw/rules/memory-index.md` 至少一个存在
- [ ] 当前不是 CI 环境（`CI=true` 时跳过）
- [ ] 自动记忆未被禁用（`CATPAW_MEMORY_DISABLED=true` 时跳过）

---

### Step 2：扫描会话历史

读取本次会话的消息记录，聚焦：

- 用户明确表达的偏好或习惯
- AI 行为被用户纠正的地方
- 用户提到的项目背景信息
- 用户反复强调的技术约定

**不提取：**
- 会话内的临时计划 / TODO
- 可以从代码库推导的内容
- 单次性、上下文高度相关的内容
- 已在现有记忆中存在的重复内容

---

### Step 3：评分筛选候选价值

对每条候选记忆，按以下标准打 **1-5 分**，**分数 ≤ 2 的自动过滤，不展示给用户**。

#### 评分标准

| 分 | 含义 | 典型特征 |
|----|------|---------|
| 1 | 不应保存 | 任务特定细节、一次性实现细节、特定文件/函数名 |
| 2 | 几乎不值得 | 模糊/显而易见、任何开发者都有的通用偏好 |
| 3 | 边界线 | 项目特定但不关键，或通用但不够具体 |
| 4 | 值得保存 | 具体且可执行的技术偏好、框架选择、编码风格 |
| 5 | 强烈建议 | 用户明确要求记住、用户纠正 AI 行为、清晰的工作流规则 |

#### ❌ 评 1-2 分的典型例子（直接过滤，不展示）

- "utils.ts 中的 calculateTotal 需要重构" → 1分（任务特定）
- "这个组件数据来自 /api/v2/items" → 1分（当前代码上下文）
- "用户喜欢整洁的代码" → 1分（太显而易见）
- "用户重视测试" → 1分（无法执行）
- "将复杂问题分解为小部分来调试" → 2分（通用调试方法）

#### ✅ 评 4-5 分的典型例子（展示并建议保存）

- "用 bun 不用 npm"（用户明确纠正）→ 5分 `feedback`
- "函数保持在 50 行以内"（具体可执行）→ 4分 `feedback`
- "前端用 Tailwind CSS"（明确技术选型）→ 4分 `project`
- "用户是美团前端，主用 React"（身份背景）→ 4分 `user`
- "运行命令前先 npm install"（具体工作流步骤）→ 5分 `feedback`

**规则：** 用户在对话中明确说"记住这个"、"下次也要这样" → 无条件 5 分。
**倾向低分**：不确定时打 3 分，只有明显有价值才打 4-5 分。

---

### Step 4：展示候选列表，等待用户确认

**只展示评分 ≥ 3 的候选**，≤ 2 分已自动过滤。**不直接写入**，先呈现候选报告：

---

#### 🧠 记忆提取候选

**本次对话筛选出 X 条（已过滤 Y 条低质量记忆），请确认：**

```
[1] 用 bun 不用 npm
    类型：feedback → 用户层（~/.catpaw/）
    摘要：用户要求包管理器统一使用 bun
    评分：5分｜用户明确纠正 AI 行为，具体可执行
    ✅ 建议保存

[2] 项目 API baseURL 是 https://api.example.com
    类型：project → 项目层（.catpaw/）
    摘要：后端接口地址（项目特定，有一定价值）
    评分：3分｜项目特定但不关键，可选择保存
    ⚠️ 可选保存

[3] 今天临时用 ES5 语法写了一段代码
    （评分 1分，已自动过滤，不展示）
```

---

请回复（支持以下任意表达方式）：

| 用户说 | 执行动作 |
|--------|---------|
| "全部保存" / "都保存" | 保存所有展示的条目（含 3 分项） |
| "保存建议保存的" / "只保存推荐的" | 只保存 ✅ 标记的条目（4-5 分），跳过 ⚠️ |
| "保存 4 分以上" / "保存高分的" | 只保存评分 ≥ 4 的条目 |
| "保存 1" / "保存 1、2" / "保存第一条" | 只保存指定序号 |
| "保存 1，跳过 2" | 精细控制各条目 |
| "跳过" / "不用了" / 不回复 | 不写入任何记忆 |

---

### Step 5：根据用户确认执行写入

收到用户确认后，对被批准的每条目，先判断是**新增**还是**更新**：

- **新增**（对应常见情况"无重复"）→ 执行完整 A→B→C 三步
- **更新**（候选列表中标注了"将更新已有记忆"）→ **只执行步骤 A**（编辑已有主题文件内容），**不追加索引行**（索引行已存在）

#### A：先写主题文件

根据 type 写入对应层：

| type | 主题文件 | 索引文件 |
|------|---------|----------|
| `user` / `feedback` | `~/.catpaw/memory/topics/<title>.md` | `~/.catpaw/rules/memory-index.md` |
| `project` / `reference` | `.catpaw/memory/topics/<title>.md` | `.catpaw/rules/memory-index.md` |

内容格式：
```markdown
---
name: <标题>
type: <user|feedback|project|reference>
created: <YYYY-MM-DD>
source: extract
---

<提取的完整内容>
```

#### B：再更新索引

追加到对应层的 `rules/memory-index.md`：
```
- [<标题>](../memory/topics/<filename>.md)｜<type>｜<≤80字符摘要>
```

#### C（双写）：user / feedback 类型额外同步到项目层用户索引副本

仅当 type 为 `user` 或 `feedback` 时执行：在项目层 `.catpaw/rules/memory-user-index.md` 末尾追加同一条目，链接使用用户层 topic 文件的**绝对路径**：

```
- [<标题>](<~/.catpaw/memory/topics/<filename>.md 的绝对路径>)｜<type>｜<≤80字符摘要>
```

- `.catpaw/rules/memory-user-index.md` 不存在时跳过（非致命错误）

---

### Step 6：检查索引上限

每次追加后检查是否触达：
- 超过 **200 行** 或 **25,000 字节** → 追加截断警告并停止继续写入

---

### Step 7：完成确认

写入完成后告知用户：

> ✅ 已保存 X 条记忆（用户层 A 条，其中 user/feedback 类已同步到项目层；项目层新增 B 条），跳过 Y 条。

---

## 行为约束（指令级）

> ⚠️ 以下是写给 AI 模型的**行为指令约束**，不是运行时强制的沙箱隔离。

提取器执行时应遵守以下约束：

| 操作 | 约束 |
|------|------|
| 读取文件（任意） | ✅ 允许 |
| 写入 `~/.catpaw/memory/topics/` 和 `~/.catpaw/rules/memory-index.md` | ✅ 允许（用户确认后） |
| 写入 `.catpaw/memory/topics/` 和 `.catpaw/rules/memory-index.md` | ✅ 允许（用户确认后） |
| 写入其他路径 | ❌ 不应执行 |
| 执行 Shell 命令 | ❌ 不应执行 |
| 网络请求 | ❌ 不应执行 |
| 最大轮次 | **5 轮**（超出应停止） |

---

## 常见情况处理

| 情况 | 处理方式 |
|------|----------|
| 会话全是代码问答，无偏好信息 | 告知"本次未发现值得记录的内容"，不展示候选列表 |
| 用户反复纠正同一问题 | 只展示一条，合并内容 |
| 候选记忆与已有记忆重复 | 先检查索引，重复则在候选列表中标注"将更新已有记忆"而非新建 |
| 进程崩溃（两步之间） | 孤儿文件留待 memory-cleanup 清理，不影响索引一致性 |
| 用户说"全部跳过" | 不写入任何内容，正常结束 |
